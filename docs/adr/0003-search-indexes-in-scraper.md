# 0003. Search indexes live in the scraper

Full-text search needs indexes the scraper database doesn't have. It has no `tsvector` or trigram index, and no index on `speech.report_id`. ADR 0001 keeps the API read-only and gives the scraper every migration, so the API can't create them. The alternative was a separate search engine such as Meilisearch or Typesense, fed by an indexer in this repo. That would give typo tolerance and facets, but it's a second datastore that has to be rebuilt every time the scraper re-parses speeches, and the scraper re-parses often. Pair Search already offers meaning-based search over the same corpus, so a second engine buys little. Search uses Postgres full-text search. The scraper owns the indexes as Alembic migrations: a GIN index over a `tsvector` of speech text and report title, and a B-tree index on `speech.report_id`. The API only queries them. If a feature needs an index the scraper doesn't have, the scraper adds it first. The API never works around a missing index with a slower query.
