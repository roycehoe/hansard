# 0006. Display what the record prints

The record sometimes prints a value that is likely wrong. Report 21556 prints column 3653 between 3562 and 3564, and the sequence suggests 3563. The scraper owns the data (ADR 0001), and it already stores the printed number with our reading in a separate note ([scraper ADR 0013](https://github.com/roycehoe/hansard-scraper/blob/master/docs/adr/0013-store-what-the-record-prints.md)). This record covers the site's half. Royce set the rule on 23 October 2026 in decision 5 of the scraper's R20 column numbers decisions, and said it holds generally:

> Store and display the number as printed (3653), never a corrected one: the data stays as close to the record as possible. The row carries a note that the printed number is likely wrong and which number the sequence suggests (3563), so the site can show a footnote or tooltip. [...] This principle holds generally: where the record prints something, store what it prints and put our reading in a note.

The site shows the value the record prints. Our reading goes in a note beside it and never takes the value's place. The first implementation is the column marker on the report page, commits 5f35a69 to 583241a on 24 Oct 2026. `api/` declares its own `ColumnNote` enum over the scraper's `columnnote` type, reads `speech.column_note` and `column_suggested` next to `column_start`, and returns all three unchanged in the report response. The margin marker shows `col. {column_start}`, the printed number. When the row has a note, the marker is a `TooltipColumnNote`: a dotted underline that opens a tooltip on hover, focus or click, plus a screen-reader label. A likely misprint reads "The record prints column 3653 here. It is likely a misprint: the columns around it suggest 3563." The suggested number appears only inside the note, and a copied paragraph citation also cites the printed column. A marker the record prints as `l79` shows `col. 179`, because the scraper stores the integer, and the note says the record prints a letter l in place of a 1. Any later feature that shows a stored value the scraper has annotated follows the same pattern: show the printed value, and offer our reading as a tooltip or footnote. The "Record what cleaning loses" fact in `CLAUDE.md` still applies to any value the site changes on the way out of the database.

## Amendment for tables printed as pictures, 21 Nov 2026

The record prints some tables, division lists and notes as inline pictures, which the scraper's parser drops, so before this change a report page showed nothing where the record printed 974 pictures in 737 reports. On 21 November 2026 Royce ruled that a report page shows our typed copy of each such picture, at the place the record prints it, and nothing of the picture itself. Under each typed copy goes a footnote link reading "source", in lower case, which opens the picture. Here our reading takes the printed value's place on the page, which the rule above forbids, so this amendment records the exception and its limits. Royce wants the typed table to be what readers, search and crawlers see, with the picture one click away for checking.

The picture stays the printed value. The scraper keeps it byte for byte in `report_picture.picture_bytes`, and the API serves it at `/api/reports/{slug}/pictures/{sha256}`. The typed copy is our reading of it ([scraper ADR 0013](https://github.com/roycehoe/hansard-scraper/blob/master/docs/adr/0013-store-what-the-record-prints.md)): two independent transcriptions and a judge that checked every cell against the picture. On the 26 pilot pictures, whose cells had been checked by hand, the copy matched 741 of 742 cells, and the one difference was the hand check's own error. A copy prints what the picture prints, misprints included: the division lists keep "Mevin Yong", "Zagy Mohamad" and "Chen Sow Mao" as printed, with no note. Before any division list showed, its names were checked against the names the scraper reads from the Votes and Proceedings (`division_vote`), and the one list with no stored names against the Parliament's roster; that check found one copy that had corrected "Zagy" to "Zaqy", and it was set back to print "Zagy". Ten pictures whose judge marked cells as uncertain got one more look at those cells, and the page shows its reading with no uncertainty note.

Tables and division lists show as typed copies, and so do the 14 pictures that print blocks of text: 13 blocks of notes under a table and one passage of quoted Bill prose in bill-60. A chart, and any other picture stored without a typed copy, shows as the picture itself, with no source link. A division list printed twice in one report shows twice, where the record prints it. The source footnote reuses the transcript's footnote style: muted small text, a 48-pixel line above, and an underlined link. The server page text (ADR 0008) prints the same typed copies at the same places as plain HTML tables and lists, with the same source link, and a picture with no copy as an `<img>`. The cost is that a reader sees our reading first, so a transcription error reads as the record's value until someone opens the source.
