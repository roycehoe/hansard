# 0006. Display what the record prints

The record sometimes prints a value that is likely wrong. Report 21556 prints column 3653 between 3562 and 3564, and the sequence suggests 3563. The scraper owns the data (ADR 0001), and it already stores the printed number with our reading in a separate note ([scraper ADR 0013](https://github.com/roycehoe/hansard-scraper/blob/master/docs/adr/0013-store-what-the-record-prints.md)). This record covers the site's half. Royce set the rule on 23 October 2026 in decision 5 of the scraper's R20 column numbers decisions, and said it holds generally:

> Store and display the number as printed (3653), never a corrected one: the data stays as close to the record as possible. The row carries a note that the printed number is likely wrong and which number the sequence suggests (3563), so the site can show a footnote or tooltip. [...] This principle holds generally: where the record prints something, store what it prints and put our reading in a note.

The site shows the value the record prints. Our reading goes in a note beside it and never takes the value's place. The first implementation is the column marker on the report page, commits 5f35a69 to 583241a on 24 Oct 2026. `api/` declares its own `ColumnNote` enum over the scraper's `columnnote` type, reads `speech.column_note` and `column_suggested` next to `column_start`, and returns all three unchanged in the report response. The margin marker shows `col. {column_start}`, the printed number. When the row has a note, the marker is a `TooltipColumnNote`: a dotted underline that opens a tooltip on hover, focus or click, plus a screen-reader label. A likely misprint reads "The record prints column 3653 here. It is likely a misprint: the columns around it suggest 3563." The suggested number appears only inside the note, and a copied paragraph citation also cites the printed column. A marker the record prints as `l79` shows `col. 179`, because the scraper stores the integer, and the note says the record prints a letter l in place of a 1. Any later feature that shows a stored value the scraper has annotated follows the same pattern: show the printed value, and offer our reading as a tooltip or footnote. The "Record what cleaning loses" fact in `CLAUDE.md` still applies to any value the site changes on the way out of the database.
