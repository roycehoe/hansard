# 0001. Read-only API

The API reads the Postgres database that `roycehoe/hansard-scraper` builds. Two repos could each own part of that schema, and then Alembic histories would fork and a column rename in one repo could break the other without warning. The alternative was to import the scraper's SQLModel classes into the API as a package. That keeps one set of models, but it ties the API's release cycle and Python version to the scraper. The scraper owns the schema and every migration. The API has no Alembic, connects through a Postgres role that can only `SELECT`, and declares its own SQLModel class for each table it reads, with only the columns it uses. A scraper schema change that breaks a read shows up as a failing API query. Nobody has to notice a migration that landed in another repo. If the API ever needs to write, for example user accounts or saved searches, those tables go in a separate schema that the API owns, and that change needs a new ADR.
