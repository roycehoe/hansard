# Hansard user stories: Plan

Input: `plans/hansard-user-stories-brief.md` (22 stories, 13 MVP, decisions 1 to 16, five scenarios). Everything in the brief is locked. This plan says how the MVP stories land in `api/` and `app/` against the scraper database as it stood on 13 October 2026. It was revised once after an adversarial review; the review's blockers and should-fixes are folded in below.

## Clarifications

Every decision in the brief is taken as resolved (human answer). The entries below are what planning added, each marked with its source.

1. **Stories in scope** (brief decision 3): A1, A2, A3, A5, B1, B2, B3, C1, C2, C3, D1, D2, F1, F2. Nothing from Next or Later. (human)
2. **The database on 13 October 2026** (codebase evidence, read-only queries). 37,929 reports, 21,707 with `markdown_content`, of which 14 hold an empty string; 1955-04-22 to 2025-04-08. Speech rows: 640,729 and moving, because another session is rebuilding them; 597,709 carry a speaker label, 580,410 are linked. 1,719 sittings, one per date, and every report date has a sitting row. Attendance 96,500 rows, 96,350 linked, 95,959 with a `location_name`; the last sitting with attendance rows is 13 August 2012, so 386 sittings have none. Memberships 1,434, every one linked to one of 573 persons. Postgres 17.11. Default text search configuration is `simple`, so every full-text expression names `english` explicitly.
3. **Existing indexes** (codebase evidence): only primary keys, `report.report_id` unique, and `speaker.person_id`. Nothing on `speech.report_id`, `speech.speaker_id`, `attendance.sitting_id`, `attendance.speaker_id`, `report.sitting_date`, and no `tsvector` index. These go in `docs/required-indexes.md` per decision 16. All seven exist on production since 14 October 2026 (scraper commit `b15908a`), with a composite `(sitting_date, parliament_number)` in place of the single-column date index.
4. **`sitting.sitting_date` is a `D-M-YYYY` string** without zero padding (`9-1-1957`). `report.sitting_date` is a timestamp at midnight. The API joins the two by formatting the date in Python as `f"{day}-{month}-{year}"` and comparing strings, which needs no index on a 1,719-row table. Where SQL has to map a sitting to a Parliament (attendance by Parliament), it uses `to_date(sitting.sitting_date, 'DD-MM-YYYY')` against `report.sitting_date::date` over the 1,719 distinct report dates. (codebase evidence)
5. **`sitting.session_no` is null for 1,506 of 1,719 sittings**; it exists for Parliaments 13 and 14 (two sessions each, 212 sittings) and one sitting of Parliament 12. Parliament, volume and sitting number for a sitting come from its reports, which always carry them. (codebase evidence)
6. **Report slug** (ADR 0004): `report_id` with every trailing `#` removed, then URL-encoded by the router. All 37,929 stripped values are distinct; 3,878 ids end in `##`; 17,830 pre-2012 ids carry an inner `#`, which travels as `%23`. The API resolves a slug by trying `slug + "#"` then `slug + "##"` against the unique index. The API returns the raw slug and never a pre-encoded one; the app encodes it with `encodeURIComponent` in the hook path and in every copied link. TanStack Router (`router-core` 1.171) encodes path params with `encodeURIComponent` and decodes matched params, verified by a node probe on 13 October 2026. (codebase evidence)
7. **Speech ordinals start at 1** in the data, not 0 as the scraper's data dictionary says, with no duplicates within a report. Anchors use the stored ordinal: `#s1` is the first speech. (codebase evidence)
8. **Speaker labels come in three shapes** (codebase evidence): office first, `The Minister for Law (Prof. S. Jayakumar)`, sometimes with a second bracket, `The Minister for Education (Mr Tharman Shanmugaratnam) (for the Senior Minister)`; member first, `Mr Chiam See Tong (Potong Pasir)`, where the bracket is a constituency; and office only, `The Prime Minister`, `Mr Speaker`. 43,020 speeches have no label at all (procedural lines such as `Question put, and agreed to.`).
9. **Transcripts are single-line markdown** with sparse inline markup: 0 contain a newline, 3,031 contain `**`, 19,020 contain `_italic_` runs, 1,510 contain a link, 13 contain HTML. The app renders bold and italic inline and shows everything else as text. No markdown library is added. (codebase evidence, planner judgment)
10. **Official record URL** (codebase evidence, from the SPRS front-end bundle read on 13 October 2026). SPRS uses hash routing. Its config holds `sprs2topic: "/search/#/topic"` and `sprs3topic: "/search/#/sprs3topic"`. The result page opens post-2012 reports as `{sprs3topic}?reportid={reportId before the first #}`, and the pre-2012 topic module reads `queryParams.reportid` as the `htmlFileName`. So: `report_version == "sprs3"` gives `https://sprs.parl.gov.sg/search/#/sprs3topic?reportid={slug}`; `sprs2` gives `https://sprs.parl.gov.sg/search/#/topic?reportid={html_file_name}`. All 21,708 sprs2 reports have an `html_file_name`; if one is ever missing, the link falls back to the SPRS search page. The `Report` model therefore carries `html_file_name`.
11. **Party strings are shown as stored** (brief decision 6). The 18 distinct values include two apostrophe forms of People's Action Party, "Unknown", "NA" and "Nominated Member of Parliament". The app never normalises them. (human)
12. **Read-only connection** (brief decision 15): the engine passes `connect_args={"options": "-c default_transaction_read_only=on -c statement_timeout=30000"}`. Verified on 13 October 2026: `SHOW default_transaction_read_only` returns `on` and `CREATE TEMP TABLE` fails with `ReadOnlySqlTransaction`. The statement timeout is the one cross-cutting mechanism this run adds; it is applied in one place for every query (R21). (human, planner judgment)
13. **Legislative Assembly memberships are filed under Parliament 1 to 12, never 0.** `speaker.parliament_number` never holds 0. `is_legislative_assembly` is set on every membership of a person who sat in the Assembly (Lee Kuan Yew's twelve rows all carry it), so it marks the person, not the membership. 113,499 linked speeches in Parliament 0 reports point at Parliament 1 memberships; David Marshall's one membership reads "Parliament 1, Labour Front". So per-Parliament counts on a Person page come from the Report's `parliament_number` (speeches) and from the sitting's date mapped to a Parliament (attendance), never from the membership's number. Parliament 0 is labelled "Legislative Assembly". (codebase evidence, from the review)
14. **Model usage** (orchestration instruction): Haiku for sweeps and EXPLAIN runs, Sonnet for implementation and drafting, Opus for the plan review, the audit and the final review. (human)
15. **Terminology outside `database/`** (brief decision 9): the CRUD class over the `speaker` table is `CRUDMembership`, ids of its rows are `membership_id`s in every signature and schema, and the raw name string on a Speech is `speaker_label`. The scraper's column names (`speaker_id`) appear only inside `database/` and inside the SQL expressions that reference them. (human)

### Decided without Royce

Each entry is a choice a skill would have paused on. The brief's answer or the recommended option was taken.

1. **B3 groups a Parliament's sittings by session where `session_no` is present for every sitting of that Parliament, and by volume otherwise, with the group heading saying which.** Session exists only for Parliaments 13 and 14 (clarification 5). Volume is always present and is the unit lawyers cite. This honours the locked story where the data allows and says so where it cannot. Royce can make it session everywhere by backfilling `session_no` in the scraper (the report markdown header carries `Session No:`), and the app needs no shape change. Flagged in the final report as a question for Royce.
2. **The Sitting page lists its Reports and links to each; it does not inline every speech.** A sitting averages 22 reports at 11.7 KB of markdown each, so the page would run to hundreds of kilobytes. The page shows each Report's title, type chip, "Text not in this archive yet" marker and position, in `speech_number` order, plus the attendance lists.
3. **Search is two endpoints and two paged groups.** `GET /search/speeches` returns speech matches and `GET /search/reports` returns title matches, each ranked and paged in SQL on its own table, each with `has_next_page` rather than a total. The page shows "Speech matches" and "Title matches" as two groups with their own Previous and Next. This keeps every CRUD method on one table and returns model rows, which R30, R35 and R47 require.
4. **Title matches with a Person filter are restricted to Reports without text.** A title has no speaker, so a Person filter cannot apply to it; restricting the title group to text-less Reports keeps B2 ("within one Person's Speeches") from being flooded with other people's Reports while scenario 2 still holds, because every Parliament 14 Report is text-less. Title matches are labelled "Title match".
5. **The text coverage notice is always shown above search results**, with the first and last sitting dates that have text (from `GET /coverage`) and a link to `/coverage`. The coverage query is cached for an hour in the app so a search does not re-count the corpus.
6. **The scraper's three attribution numbers are app constants dated 13 October 2026 and scoped to Parliaments 0 to 11**, taken from the scraper's `docs/vision.md`: 97.61% of speech rows with a speaker label are linked to a person (564,509 of 578,359, excluding collective "hon. Member" references and stage directions); 90.42% of all speech rows are linked (564,509 of 624,332, counting rows with no label); 96.81% of the characters of body text sit in a linked speech. The API cannot compute them; they need the scraper's parser. The coverage page says where they come from, when they were measured and what each counts, in plain words. Live counts (reports, text reports, speeches, linked speeches, persons, memberships, sittings, attendance rows, linked attendance rows) come from the API as counts, with no live percentage beside the dated ones.
7. **Citation format** (D2, Singapore Academy of Law style): `Singapore Parliamentary Debates, Official Report (8 April 1993) vol 61 (Prof S Jayakumar, Minister for Law)`. Rules: the name is the first bracket when the label starts with `The `; later brackets are ignored; the office is the text before the first bracket with the leading `The ` removed; dots are stripped from the name; a member-first label gives the text before the bracket as the name and no office; an office-only label gives the office alone (`Prime Minister`); a label with no bracket and no `The ` is used whole (`Mr Speaker`). Parliament 0 Reports cite `Singapore Legislative Assembly Debates, Official Report`, which Royce should confirm. A Report citation omits the speaker bracket. The copy action's toast says the column number will be added when the archive has it. Worked examples go in the execution plan.
8. **`crud/` returns model rows and primitives only.** Aggregates come back as one `{key}_to_{value}` dict method per value (R35: split the method, no dataclass, no tuple). Paged lists over `report` and `speech` return model rows. Nothing in `crud/` spans two tables except joins used to filter and sort a single table's rows.
9. **List methods over `report` defer `markdown_content`.** A sitting's reports or a page of person reports would otherwise pull 250 KB of markdown per request. "Has text" means `markdown_content IS NOT NULL AND markdown_content <> ''`, and comes from a separate ids method.
10. **Page size** is 20 by default and capped at 100, and a search query is capped at 200 characters, all validated by FastAPI `Query` bounds. A bad date or page number is a 422 from FastAPI, not a custom exception. A query of stop words only, or of negations only, runs and returns nothing or everything; the empty state says common words are ignored, and the negation case is recorded in `docs/required-indexes.md` as one the GIN index cannot serve.
11. **`ts_headline` options**: `StartSel=<mark>, StopSel=</mark>, MaxWords=35, MinWords=15`, computed only for the page's rows through a `{id}_to_headline` method. The app splits the snippet on those two literal tags and renders `<mark>` with the `highlight` tokens. No `dangerouslySetInnerHTML`.
12. **Ordering and paging are stable**: relevance sort is rank, then sitting date newest first, then id; date sort is sitting date newest first, then rank, then id.
13. **Parliament 0 is labelled "Legislative Assembly"** everywhere the app prints a Parliament number. In the People filter, the Legislative Assembly option selects memberships whose `is_legislative_assembly` flag is set, which is the data's own marker for former Assembly members (clarification 13). The People filter's Parliament options run 0 to 15 (memberships reach 15); the search page's Parliament options come from `GET /parliaments` (reports reach 14).
14. **`GET /parties`** returns the distinct stored party strings for the People filter.
15. **The footer's Browse links point at the new routes** (`/sittings` for sitting date and Parliament, `/people` labelled "By person") and "How the record is parsed" points at `/coverage`. "Official Report" points at `https://sprs.parl.gov.sg/search/`. Links with no page yet keep `#`.
16. **The nav gains Search, Sittings, People and Coverage** and keeps Design and Palette.
17. **The header search box submits to `/search?q=`.**
18. **`plans/` stays committed.** The foundation run committed its plans; the feat-plan `.gitignore` prompt is skipped.
19. **A person URL with a wrong slug redirects** with `replace: true` after the person loads (ADR 0004). A slug with no leading integer is a not-found page with no API call.
20. **Page-level fetch errors use a thin `NoticeError{Feature}` per feature** wrapping the foundation's `NoticeError` layout piece, as `app/STYLE.md` "Error Notices" asks. A 404 renders a `NoticeNotFound{Feature}` with a way back, and the query client does not retry a 404.
21. **The year table on the coverage page and the two tables on the person page use the `Table` primitives directly**, not TanStack Table. They have no sorting, filtering or paging, so the four-file split in `app/STYLE.md` "Tables" does not apply; this carve-out is recorded here and in the execution plan.
22. **Pure helpers live in `lib/format.ts`, `lib/citation.ts` and `lib/transcript.ts`**, following the foundation's `lib/colour.ts` precedent for a helper family with its own subject. `lib/utils.ts` keeps `cn` and the small shared helpers (`buildQueryString`, `parsePersonSlug`).
23. **Required indexes** (decision 16): the five B-trees the brief names plus two GIN expression indexes, `to_tsvector('english', transcript)` on `speech` and `to_tsvector('english', title)` on `report`. The sitting table (1,719 rows) gets none. The file also records that `ts_rank` recomputes the vector for every matched row because an expression index stores none, and offers Royce a stored generated `tsvector` column as the alternative.
24. **Data defects shown, not hidden.** A sitting without attendance rows says "Attendance for this sitting isn't in this archive yet." A Report with text but no speeches says the text could not be split into speeches and links to the official record. A Person's per-Parliament counts carry a note that speech text ends 13 August 2012 and attendance lists end the same day, so later Parliaments show no counts rather than zeros. The known-gaps list on the coverage page names: no text from 10 September 2012; Parliament 15 missing; no attendance lists after 13 August 2012; Legislative Assembly memberships filed under Parliament 1; 1,691 refetched reports whose position number is per month rather than global, so their order within a sitting can be wrong; column numbers absent; speech links best-effort; person addresses that can change when the scraper corrects who is who; party names as stored; garbled characters in some titles; "The Chairman" speeches that cannot be linked.
25. **Sitting order stays `speech_number`** (A3 is locked) even though the refetched rows sort wrongly. The defect is listed as a known gap and flagged to Royce as scraper work (store the global `sno`).

## Test Seams

1. **The API's HTTP endpoints**, exercised with `curl` against the running API connected read-only to the real database. Chosen because they are the highest public seam the backend has and every story's data reaches the app through them. Observes response shape, 404s for unknown slugs, dates and person ids, pagination flags, and the exact SQL (via `EXPLAIN` of the same expressions).
2. **The app's routes**, checked with `pnpm build`, `pnpm lint`, `pnpm exec prettier --check .` and `pnpm contrast`, then by the final Opus review of the diff against `app/STYLE.md` and WCAG 2.2 AA. There is no browser in this run, and a curl of a single-page app returns only the shell, so the router behaviour is verified by the node probe recorded in clarification 6.

## Implementation Steps

### API

1. **Engine, session and models.** Add `get_session()` to `database/engine.py` and the read-only and timeout connection options (clarification 12). Declare one SQLModel class per table with only the columns used: `Report` (`id`, `volume_number`, `parliament_number`, `sitting_number`, `sitting_date`, `speech_number`, `title`, `subtitle`, `report_id`, `report_type` as `str`, `html_file_name`, `markdown_content`, `report_version`), `Speech` (`id`, `ordinal`, `speaker`, `transcript`, `report_id`, `speaker_id`), `Sitting` (`id`, `session_no`, `sitting_date`), `Attendance` (`id`, `speaker_name`, `location_name`, `is_present`, `sitting_id`, `speaker_id`), `Speaker` (`id`, `name`, `party`, `parliament_number`, `is_legislative_assembly`, `is_member`, `person_id`), `Person` (`id`, `canonical_name`). `report_type` stays `str` on the model: a SQLAlchemy `Enum` column would map by member name and fail on `oral-answer`. Do not import the scraper's models. Do not add relationships.
2. **Enums.** `enums.py` with `ReportType` (the 23 stored strings), `SearchSort` (`RELEVANCE`, `DATE`).
3. **Exceptions.** `exceptions/base.py` with `ErrorCode`, `ErrorSpec`, the `ERRORS` mapping (the one mapping constant the style guide allows) and `AppHttpExceptionBase(HTTPException)` carrying `{error_code, message}` as `detail`. Domain files: `exceptions/report.py` (`ReportNotFoundException`, 404), `exceptions/sitting.py` (`SittingNotFoundException`, 404), `exceptions/person.py` (`PersonNotFoundException`, 404). No arguments on any exception.
4. **Pure helpers in `utils/`.** `utils/report_slug.py`: `get_report_slug`, `get_report_id_candidates`. `utils/official_record.py`: `get_official_record_url(report_id, report_version, html_file_name)` per clarification 10. `utils/person_slug.py`: `get_person_slug`. `utils/sitting_date.py`: `get_sitting_date_text`. `utils/like_pattern.py`: `escape_like_pattern` for `%` and `_`.

   - `CRUDSpeech`: `get_all_by_report_id` (ordered by `ordinal`), `get_parliament_number_to_speech_count_by_membership_ids` (join report), `get_report_id_to_speech_count_by_membership_ids(membership_ids, limit, offset)` (grouped by report, ordered newest first; the dict preserves that order), `get_count`, `get_count_with_membership_id`, `get_all_by_query_filtered(query, parliament_number, date_from, date_to, report_type, membership_ids, sort, limit, offset)` (join report for the filters and the date sort), `get_id_to_headline_by_ids(speech_ids, query)`.

## Resolved Tradeoffs

- **Postgres full-text search in the API, with indexes owned by the scraper** (ADR 0003, brief decision 7). The queries use the exact expressions in `docs/required-indexes.md` so the GIN indexes apply the day they exist. Until then they were sequential scans and B1 and B2 were marked unverified. B1 and B2 are verified end to end against production on 14 October 2026, after the scraper's commit `b15908a` created the indexes: `GET /search/speeches` answers 200 for "housing estate" and for a person-filtered search. A common term such as "government" still answers `503 search.timed_out`; `docs/required-indexes.md` records the measured times and plans.
- **Two search endpoints instead of one union** (Decided without Royce 3). A union would page both arms together but needs a cross-table CRUD class and composite rows, which the style rulings forbid. Two groups cost one extra request per search and keep the layer rules intact.
- **Slug from `report_id`, not the numeric id** (ADR 0004). Verified unique after stripping; lookup uses the existing unique index with two candidates rather than an expression index.
- **Reports, not raw speeches, on the Sitting page** (Decided without Royce 2), on page-size grounds.
- **Per-value dict methods for aggregates** (Decided without Royce 8). More statements per request, each cheap and each a plain mapping; no composite type to maintain.
- **`has_next_page` instead of totals for search and person reports** (Decided without Royce 3). The numbered pager on `/design` stays for client-side tables.
- **Attribution figures as dated, scoped app constants** (Decided without Royce 6).
- **No markdown dependency** (clarification 9).
- **Pending, not blocking: `session_no` and the global `sno`.** Both are scraper work for Royce; the app adapts without a shape change once they land.

## Gaps and Breakage

- Speech counts move while this run executes because another session is rebuilding speech rows. Curl checks compare shapes and ordering, not counts.
- The `english` configuration must be a SQL literal in the SQLAlchemy expression. With a bound parameter the planner sees `to_tsvector($1, transcript)` and will never use the expression index. Verified: `literal_column("'english'")` compiles to `to_tsvector('english', transcript)`.
- `ts_rank` recomputes the vector per matched row; a common word such as "government" matches roughly 94,000 speeches. Acceptable in development, recorded in `docs/required-indexes.md` with the stored-column alternative for Royce.
- A `#s{ordinal}` target does not exist until the report query resolves, so the browser's own fragment jump misses; the page scrolls and focuses after render.
- The 1,691 refetched reports sort wrongly within 390 sittings because their `speech_number` is per month. Shown as stored; known gap.
- `report.title` for about 2,500 budget and president-address rows carries garbled characters (`â€™`). Shown as stored; known gap.
- Person ids are rebuildable (ADR 0004). Known gap, worded for readers.

## Assumptions

1. The pre-2012 SPRS topic page accepts `#/topic?reportid={html_file_name}`. Read from the bundle's topic module, not clicked, because this run has no browser. Royce should open one link of each form once; if the pre-2012 form is wrong, only `utils/official_record.py` changes.
2. `psycopg` honours the `options` connection parameter. Verified on 13 October 2026.
3. `report.sitting_date` values are all at midnight, so `sitting_date < date_to + 1 day` is the inclusive upper bound and `>= date_from` the lower.
4. Every sitting date in `report` has a `sitting` row (verified today, 0 missing). `GET /sittings/{date}` answers from the reports and treats a missing sitting row as not found.
5. TanStack Router encodes `#` in a path param as `%23` and decodes it on read. Verified by a node probe against `@tanstack/react-router` 1.170 on 13 October 2026.
