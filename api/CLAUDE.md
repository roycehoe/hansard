# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`api/` is a FastAPI backend for the hansard web app. It reads a Postgres database of Singapore Parliament Hansard records. That database is owned by a separate scraper repo at `roycehoe/hansard-scraper`, and the API is **read-only** against it.

## Setup and commands

Python 3.15 is pinned in `api/.python-version` and in `requires-python`. Dependencies are managed with **uv**. Run everything from `api/`.

```bash
# Install dependencies
uv sync

# Run the development server (localhost:8000)
uv run fastapi dev

# Lint (run before every commit)
uv run ruff check .

# Format (run before every commit)
uv run ruff format .

# Type check (fails only on errors not in .basedpyright/baseline.json)
uv run basedpyright
```

Dependencies: `fastapi[standard]`, `sqlmodel`, `pydantic-settings`, `psycopg` (v3).

Ruff config is `[tool.ruff.lint] select = ["I", "F"]`, so lint covers import order and unused names only. `ruff format` is the formatter and is enforced.

**Tests.** `api/tests/` holds the pytest suite. Run it from `api/`:

```bash
# Tests that need no database (what CI runs)
uv run pytest -m "not database"

# Every test, including those marked `database`
uv run pytest
```

The no-database run needs Node and `app/node_modules` (run `pnpm install` in `app/`). `tests/test_api_contract.py`, the contract check, starts `node scripts/api-interfaces.ts` in `app/` to list the frontend's response interfaces and compares their field names and nullability with the API's OpenAPI schemas. It does not compare enum values, so a changed enum member passes it.

The tests marked `database` read real rows, so they need the scratch database: a copy of the scraper's schema and data at `postgresql+psycopg://user:password@localhost:5435/hansard_launch`. `tests/conftest.py` sets `DATABASE_URL` to it before any project import and stops the session if `settings.database_url` resolves anywhere else, so no test can reach the database in `api/.env`. One database test seeds a `refresh_run` row through a separate writable test engine and deletes it; the API code itself never writes. `tests/test_schema_drift.py` also carries the `schema_drift` marker. It selects every column of each model with `LIMIT 0` and reads no rows. The `schema-drift` job in `.github/workflows/ci.yml` builds the scraper master's tables with its `alembic upgrade head` in an empty Postgres 17 with rum, then runs `pytest -m schema_drift`; the `api` job leaves it out because it carries `database`. Do not write new tests unless explicitly asked; the existing ones must pass.

**No pre-commit hooks.** Do not add any without being asked. The only auth is HTTP basic auth in `website.py`, added on 18 October 2026 for the private launch; the API in `main.py` has none. It has been off on the live site since 20 October 2026, because `.do/app.yaml` sets `PUBLIC_MODE` to `true`, and any other value turns it on.

## The database contract

The scraper repo owns the schema and every Alembic migration. This API only reads.

- **No Alembic here.** The API has no migrations and never changes the schema.
- **Read-only role.** The API connects through a read-only Postgres role. Do not write code that inserts, updates or deletes rows.
- **Own models.** The API declares its own SQLModel classes, one per table it reads, once endpoints exist. It does not import the scraper's models.
- **Tables owned by the scraper:** `hansard_website_response`, `report`, `speech`, `hansard_sitting_date_response`, `sitting`, `attendance`, `speaker`, `person`, `personnamespelling`, `partyaffiliation`, `refresh_run`, `report_asker`, `report_link`, `bill`, `billreport`, `act`, `acthistoryentry`, `billkey`, `billreportspeaker`, `billstageline`, `attendance_office`, `office_printed_range`, `report_put_to`, `ministry`, `office_title_ministry`, `ministry_see_also`, `report_participant`, `attached_file`, `attached_file_pointer`, `division`, `division_vote`, `division_party_count`, `minutes`, `minutes_division`, `leave_period`, `leave_period_printing`, `seat_holding`. The scraper's `CLAUDE.md` describes them. The last three hold leave periods and seat history; they exist once the scraper's migration `e3b7c1d94a62` and the API read grant are applied, and only the unreleased endpoints read them. `refresh_run` holds one row per daily refresh; `GET /refresh` and the `attribution` field of `GET /coverage` read the latest `SUCCEEDED` row and answer as if the table were empty while the table or the API role's `SELECT` grant is missing.
- **A schema change is a scraper change.** If an endpoint needs a column that does not exist, make the change in the scraper repo, then update the matching model here.

The layer table below is the full design.

| Layer | Responsibility | Forbidden |
|---|---|---|
| `routers/` | Route handlers. Validate input, call one service function, return the result. | Business logic, calling `crud/` or `database/` directly |
| `database/` | The engine and the SQLModel classes for tables the API reads. | Logic of any kind, importing the scraper's models |
| `settings.py` | All env-based configuration. | Reading `os.environ` elsewhere |
| `main.py` | App construction, router mounting. | Business logic |
| `services/` | Business logic. Module-level functions, one file per domain. | Raw SQL, session handling beyond what a router passes in |
| `crud/` | Database reads through SQLModel sessions. Class-based, one class per table. | Business logic, HTTP calls, writes |
| `schemas/` | Pydantic request and response models. | Database access, logic |
| `exceptions/` | Custom exception hierarchy. `base.py` defines the base types. | Exceptions that take arguments |
| `utils/` | Pure functions with no side effects. Any layer may import from here. | Database access, HTTP calls, importing from layers above |
| `validators/` | Input validation called from routers or services. | Session use, I/O |
| `middleware/` | Request-path middleware registered in `main.py`, and concerns that compose calls across gateways or services. | Single-service logic |
| `gateway/` | Thin wrappers around one external service each. | Interpreting failures, business logic |

Notes on the layers that matter now:

- **Routers** call one service function and return. A router never calls `crud/` or `database/` directly.
- **Terminology.** A row of the `speaker` table is a Membership everywhere outside `database/`: `CRUDMembership`, `membership_ids`, `membership_id_to_person`. The raw name on a speech is `speaker_label`.
- **Indexes are the launch gate.** `docs/required-indexes.md` lists every index the API's queries need, with the index definitions the scraper migrations build. All nine exist on production: six since 14 October 2026 (scraper commit `1f0d8ef`), `ix_speech_transcript_tsv` since 17 October and the rum index `ix_speech_transcript_tsv_rum` since 18 October (`aed4137`). A server that runs those migrations needs the `rum` extension installed (`postgresql-17-rum` on Debian). Without the indexes the queries are sequential scans, and the speech full-text search exceeds the statement timeout and answers `503 search.timed_out`. The ninth, `ix_speech_transcript_tsv_sitting_date_rum`, and the column `speech.sitting_date` came with scraper migration `c93f77e499cc`, on production since 18 October 2026. The `Speech` model reads that column and word search orders and filters by it, so this API cannot run against a database without that migration: every statement that selects a speech would fail. The `Speech` model also reads `speech.report_type`, from scraper migration `82478ba59541`, so the API cannot run without it. Scraper migration `6b3a29f6f809`, on production since 21 October 2026, gave `ix_speech_speaker_id` and `ix_attendance_speaker_id` `INCLUDE` columns and added `ix_report_id_parliament_number`, so the person page's reads are index-only scans. The API runs without it, but heavy members' pages read thousands of heap pages each. The `ReportAsker` model reads the table `report_asker`, from scraper migration `52f4f7b77f1f`, so a parliamentary question's report page fails on a database without it. The tables behind the unreleased endpoints have their own sections, measured on a local copy; production gets those indexes with the tables' scraper migrations.
- **`/coverage` and `/parliaments` cache in-process until a refresh run finishes**, as module state in `services/coverage.py` and `services/parliament.py`. `website.py` fills both at startup on a background thread (`middleware/cache_fill.py`), so the first visitor after a deploy does not wait for the computation. The thread replaces both answers within 15 minutes of a `refresh_run` row getting its `finished_at`, whatever the run's status, and a request computes an answer only while none is stored. `main.py` has no startup hook, so `uv run fastapi dev` fills them on the first request and never recomputes. New figures can take up to about 2 hours 15 minutes to reach a visitor: up to 15 minutes until the next check, up to an hour in the response cache, then up to an hour in the browser or Cloudflare. Restart the API after a write that creates no `refresh_run` row, such as a supervised script, a link round or a migration.
- **The sitemap is built from the database and cached like `/coverage`.** `services/sitemap.py` writes `/sitemap.xml` (an index) and `/sitemap-{pages,sittings,people,acts,reports}-{n}.xml` (at most 20,000 URLs a file, about 49,500 URLs in all) for `SITE_URL`, gives each sitting and report entry its sitting date as `<lastmod>` and people and Act entries none, leaves out taken-down reports and reports with no text, and fills at startup and after each refresh run with the other two caches. While `SITE_URL` is unset, every sitemap path answers 404. A report, person or sitting page that does not exist answers 404 from `middleware/frontend.py`, which reads the answer from the preview lookup; that lookup caches only found previews (for an hour), so a page added by a refresh answers 200 straight away, even if someone asked for it before the refresh.
- **Every GET answer with status 200 is cached for an hour** by `middleware/response_cache.py` and sent with `Cache-Control: public, max-age=3600`, so browsers keep a copy for up to an hour too. The cache is process memory: a restart or deploy empties it. Behind basic auth the header goes out as `private`. A report taken down after its answer was cached keeps serving until the next restart.
- **Searches are limited to three at once across both search endpoints.** `GET /search/speeches` and `GET /search/reports` share one counter (`_MAX_RUNNING_SEARCHES`), and so does `GET /reports/{report_slug}/matched-words`, which also runs on the search engine; the fourth search answers `429 search.busy` without touching the database. One search page sends a speech request and a report request, so two visitors searching at the same moment can see the report half refused. Visitor searches run on the second engine (pool of 3, overflow of 2) with a 10-second `statement_timeout`, and one that passes it answers `503 search.timed_out`. `date_from` and `date_to` must fall between 1 January 1900 and 31 December 2100, or the answer is 422. `page` stops at 50 (`MAX_SEARCH_PAGE`), so a deep offset cannot hold a search slot. At the app's 20 results a page, page 50 ends at the 1,000th counted match. Page 51 answers 422, and page 50 reports no next page.
- **`constituency` on `GET /search/speeches` is a seat filter.** It matches the attendance lists' `location_name` by exact name, case and a trailing GRC or SMC ignored, and hyphens and runs of spaces folded to one space on both sides, so Tampines does not match Tampines Changkat. A name matching no seat answers 404 `search.constituency_not_found`. `GET /people` takes no name parameter (the app ranks typed names itself); its `constituency` parameter keeps a substring match on the attendance lists' `location_name`. A speech counts only when its date falls between the first and last sittings its Membership attended for that location. A Membership covers a whole Parliament and some sat for two seats within one, so the Membership alone is not enough. Speeches made from the chair are left out: a speaker label that is a chair title (Mr or Mdm Speaker, Deputy Speaker, The Chairman, with or without a name in brackets) is credited to the presiding member, and without the rule a Speaker's seat opens on procedure. The person filter keeps them. The app drops a trailing GRC or SMC before it sends the name.
- **`act` on `GET /search/speeches` keeps the speeches in the debates on one Act.** It takes an Act's `sso_code` (at most 32 characters, no NUL byte) and matches the debate reports of every Bill linked to the Act, omnibus Bills included, leaving out reports on the takedown list. It combines with every other filter and with words. With `report` also set, a speech must sit in a report that both filters allow. `act` alone counts as a filter, but a query of only excluded words with `act` still answers 422 `search.excluded_words_only`; only a person or seat lifts that. An unknown code answers 404 `act.not_found`. An Act with no linked report matches no speech, so the answer is empty and not unfiltered. The `act` filter is not behind `IS_UNRELEASED_ENDPOINTS_ENABLED`. `GET /search/reports` has no `act` parameter.
- **`GET /reports/{report_slug}/links` lists the reports linked to one report, and answers 404 `endpoint.not_found` while `IS_UNRELEASED_ENDPOINTS_ENABLED` is off.** It reads `report_link` (scraper migration `e7b2c4d9f1a6`, which production does not have yet). A row is one printed citation, stored with the report that prints it. The service (`get_report_links` in `services/report.py`) returns a reply or continuation row only for the report that prints it, and a correction row for both reports. A pair of corrections printed in both directions returns one entry, with the viewed report's own `printed_citation`. `relation` is `corrects`, `corrected_by`, `refers_to` or `continues`: a correction report corrects the report it is linked to, and a link to or from a report that was taken down is dropped. Each entry carries the other report's title, subtitle, type and sitting date as stored, and the citation as printed (ADR 0006). The model leaves out `rule`, which no response uses. An unknown slug answers 404 `report.not_found` and a taken-down report 410, as `GET /reports/{report_slug}` does. Reads use `uq_report_link_source_target_type` (source) and `ix_report_link_target_report_id` (target); both plans were index scans on the scratch copy. Until the table exists, the schema-drift job fails and the endpoint cannot read it when the setting is on.
- **Leave periods and seat history are three unreleased endpoints.** `routers/leave_period.py` serves `GET /people/{person_id}/leave-periods` and `GET /leave-periods/latest-sitting`, and `routers/seat.py` serves `GET /seats?constituency=<name>`. Both routers pass `validate_can_read_unreleased_endpoint`, so each answers 404 `endpoint.not_found` while `IS_UNRELEASED_ENDPOINTS_ENABLED` is off. They read `leave_period`, `leave_period_printing` and `seat_holding` (scraper migration `e3b7c1d94a62`, grant in `docs/api-database-role.md`). A person's leave periods come newest start first with undated periods last, each with every printing the record made of it, and a person with none gets 200 and an empty list. Every printing carries the text the record prints (`printed_name`, `carried_name`, `printed_from`, `printed_to`, `printed_line`, `printed_heading_from`, `printed_heading_to`, `office_printed`) beside our reading (`start_date`, `end_date`, `entry_format`, `name_source`, `year_source`, `office_source`), as `docs/adr/0006-display-what-the-record-prints.md` asks. The office is the one at the sitting that printed the list, which may differ from the office held during the leave. `GET /leave-periods/latest-sitting` answers the latest sitting that has any printing, with the printings that cover it, and 200 with a null `sitting_date` and an empty list while no printing is stored. `GET /seats` compares the name through `get_folded_location_name` against the stored `seat_holding.division_key`, so a trailing GRC or SMC, case, hyphens and spacing do not matter, and a name that matches no division answers 404 `seat.constituency_not_found`. Holders come oldest first, one row per Member and division. Their first and last sitting dates bound the Member's sittings in the division and do not show an unbroken term; `sitting_count` shows the gaps. The response's `constituency` is the printed `location_name` of the latest holder. The three response shapes have TypeScript interfaces under `app/src/api/people/`, `leave/` and `seats/` that no component imports.
- **The offices endpoints are unreleased.** `routers/office.py` serves five read-only GETs under `/offices`, behind `validate_can_read_unreleased_endpoint`, so each answers 404 `endpoint.not_found` while `IS_UNRELEASED_ENDPOINTS_ENABLED` is off, and no component calls them. `/offices/ministries` lists the 48 ministry groups with the count of titles, of reports put to and of reports answered. `/offices/ministries/{ministry_id}` lists the printed titles grouped under one, with each official see-also note. `/offices/ministries/{ministry_id}/questions?by=put_to|answered_by` pages the reports newest first, each with its put-to phrases and its answerers. `/offices/memberships/{membership_id}/printed-ranges` lists a Member's printed ranges in date order, each end carrying the sitting date, the exact attendance line and the rule that found the office. `/offices/reports/{report_slug}` gives one report's put-to and answered-by rows. Put-to and answered-by are separate facts: each is read from its own table and neither fills in the other. A ministry is a group of printed titles, so no response says a ministry existed or that a Member held an office between two prints. The titles go out as printed (`office_printed`, `printed_text`, `entry_line_printed`) beside any ministry reading. Reports on the takedown list leave out of every count and list, and the report lookup answers 410 `report.taken_down` for one. An unknown ministry answers 404 `office.ministry_not_found` and an unknown Membership 404 `office.membership_not_found`. `GET /people/{person_id}/printed-ranges` (`routers/person_office.py`, behind the same setting) lists every Membership of a person, oldest Parliament first, each with its printed ranges in the shape of the Membership endpoint, and an empty `ranges` list where none is printed; it reads one query of ranges for all the Memberships, and a second only for a Parliament 1 range that starts before 8 December 1965. Such a range is split at that date: the part before is returned under an extra entry with `parliament_number` 0 (the Legislative Assembly), the same `membership_id` and `is_continued_into_parliament_1` true, and the part from 8 December 1965 stays in the Parliament 1 entry. Each part counts the sittings of the range on its side of the date and takes its first or last print from the attendance line of that side's first or last sitting. Stored ranges do not change, and an unknown person answers 404 `person.not_found`. It reads only the tables of the offices grant in `docs/api-database-role.md`, so it needs no new grant.
- **`GET /refresh` is the footer feed.** It reads the latest `SUCCEEDED` `refresh_run` row: the last sitting date with text and the date the run finished (as a Singapore date). Halted, failed and running rows are never read. While no `SUCCEEDED` row exists, or the table or grant is missing, both fields are null and the app shows no footer line. The response cache holds this answer for an hour like any other GET, so the footer can trail a finished run by up to an hour, plus the browser's hour.
- **`GET /coverage` is the only source of published figures.** Besides the counts, it carries `attribution`: the per-Parliament attribution shares, read from the latest `SUCCEEDED` `refresh_run` row whose `figures` is a JSON object. `all_linked_share` and `text_share` count credited rows (no label, a `speaker_id`) with linked rows, as the scraper does; `named_linked_share` counts linked rows only, and figures stored before the scraper wrote `credited_row_count` and `credited_character_count` count linked rows only. Bad `figures` JSON counts as no figures, and so does a missing table or grant, or a dropped connection or a timeout on that read. The read runs in its own session, so its failure cannot fail the counts. Then `attribution` is null and the app keeps its hand-kept figures. The figures and their method are on the site's `/coverage/methods` page. No supervised write stores figures yet, so they move only with a scheduled run that adds speech rows, and reach a visitor within about 2 hours 15 minutes with no restart.
- **Preview-bot fetches go to GoatCounter**, because the API cannot write to the database (`docs/adr/0001-read-only-api.md`) and process memory resets on every deploy. `services/preview_fetch.py` sends one event hit per fetch through `gateway/analytics.py` in a task on the event loop, so the bot's response does not wait. The hit's path is `preview-fetch/` plus the request path (no query), its `ref` is the bot name, and its `session` is a fresh random id. It sends no IP or user agent. A path that is not one of the site's routes, or is longer than 300 bytes, counts as `other`. A timeout or a non-2xx answer, 429 included, logs one warning and drops the hit. Nothing is retried or buffered. It needs `GOATCOUNTER_SITE_URL` and `GOATCOUNTER_API_TOKEN`; while either is unset, nothing is sent. Royce creates the token in GoatCounter (Settings, API) with permission to record pageviews. In private mode a bot gets 401 before the counter, so counting happens only in public mode.
- **Searches and `search.busy` refusals are counted in process memory**, for the load test only. `services/search_count.py` keys each count by Singapore date and `SearchEndpoint` (speech search, report search, matched words). `search_count` is every request that asked for a search slot, refused ones included; a search answered from the response cache or by Cloudflare never asks, so it is not counted. `refusal_count` is the ones answered `429 search.busy`. It keeps at most 10,000 keys and loses them on restart or deploy. `GET /search-counts` reads them; the load test reads it before and after one run. For live traffic, read the `search-busy` event in GoatCounter instead (the app sends it when a busy notice shows).
- **Bill and act endpoints.** They read the scraper's `bill`, `billreport`, `billkey`, `billreportspeaker`, `billstageline`, `act` and `acthistoryentry` tables, and need the `hansard_api` grant in `docs/api-database-role.md`. A Bill appears only with a `billkey` row and at least one report that is not taken down. A person appears on a Bill or an Act only with a Member row in such a report. A Member row whose speech rows all carry a chair label (Mr or Mdm Speaker, Deputy Speaker, The Chairman, with or without a name in brackets) is left out, so presiding over a Bill is not speaking on it (Royce, 10 Nov 2026). A row that also has a speech under the Member's own label stays. Every count is per role (READING and BUDGET_DEBATE) and is never merged. `printed_speakers` goes out beside the counts: the label printed on the first row of each counted Member row. Each Bill on `GET /people/{person_id}/bills` also carries `reports`: one entry per report the Member has a counted row in (slug, sitting date, Parliament and role), oldest first, so a chair-only or taken-down report never appears. `bill_key` is never the slug of a taken-down report. No endpoint serves the text of an Act. Every column the queries filter on is indexed in the scraper's models, and `docs/required-indexes.md` lists those indexes.
- **The Act endpoints carry what the Act page shows.** `GET /acts` lists every Act's `sso_code` and `title`, ordered by title, with no paging, behind the same release check as the other Act routes. `GET /acts/{sso_code}` lists the history entries newest first, which is `ordinal` descending: `ordinal` is the print order on SSO and dates are not monotonic, so the answer claims no date order. A linked Bill carries its `reports`: `report_slug`, `title`, `report_type`, `sitting_date` and `stages`, sorted by sitting date, report type and slug. `stages` holds each distinct stage of the report's stage lines once, in print order, and is empty when the report has no stage line. A report on the takedown list is left out of `reports` and of `stages`, and a Bill that sits on two entries of one Act shows its reports under both. `sso_url` is `https://sso.agc.gov.sg/Act/` followed by the percent-encoded `sso_code`, built by `utils/act_url.py`; the API does not check that SSO serves it. `GET /acts/{sso_code}/people` is unchanged, because it reads the entries only for their Bill ids.
- **The attached file endpoints are unreleased** (`routers/attached_file.py`, both answer 404 `endpoint.not_found` while `IS_UNRELEASED_ENDPOINTS_ENABLED` is off). The report endpoint lists a report's download links in the order the record prints them, each with the link's words and the file it ties to, and answers 410 for a taken-down report. The sitting endpoint lists every file the sitting lists, tied or not, with the pointers of its reports, and puts the pointers that tie to no file in `unlisted_pointers`. It leaves out a taken-down report's pointers, and a file whose every pointer is on one; a listed file with no pointer stays. A `url` is the SPRS download address built from the stored value with `/` kept and everything else percent-encoded, or null for the placeholder path the record prints. Every address goes out as built, whether or not SPRS answers it (`docs/adr/0006-display-what-the-record-prints.md`). The responses never carry `href`, the printed file path, a table id or the tier that tied a paragraph. The tables need `SELECT` for `hansard_api` before the setting is switched on (`docs/api-database-role.md`).
- **The division and minutes endpoints are unreleased** (`routers/division.py` and `routers/minutes.py`, all three answer 404 `endpoint.not_found` while `IS_UNRELEASED_ENDPOINTS_ENABLED` is off, and no component calls them). `GET /divisions` pages divisions newest sitting first with the id as tie-break, and takes `parliament_number`, `date_from`, `date_to` (both ends included) and `report_slug`. `GET /divisions/{division_id}` adds the printed list, the vote rows of each stored list, the party breakdowns and the paired minutes division. `GET /minutes` pages the Votes and Proceedings files newest sitting first and takes `status`, `date_from` and `date_to`. A division is tied to a report by `sprs_report_id`. A division of a taken-down report leaves out of the list and its total count (in SQL, through an outer join on `report`, so a division with no report stays), and its own page answers 410 `report.taken_down`. A division that only the minutes show has no report, so its `report_slug` and `report_title` are null and the takedown list never reaches it. An unknown id answers 404 `division.not_found`. The counts, the printed counts line, the printed list and each printed name go out as stored (`docs/adr/0006-display-what-the-record-prints.md`) beside our reading: the Membership a name links to (`membership_id`, null when no single Member fits), the party and its uncertainty flag, and the list status. A count the record does not print is null, not 0. `GET /minutes` never carries the extracted text, the file hash, the status note or a capture. The tables need the grants in `docs/api-database-role.md` before the setting is switched on; `minutes` takes a column grant, so a query that selects its text columns fails.
- **`crud/` is read-only here.** The rules in `STYLE.md` about CRUD writes stay in the guide, but this API has no write path.
- **Raw SQL** is limited to the database tests (seeding and reading `refresh_run`, the read-only write checks, the `SHOW statement_timeout` check and the phrase search test's truth query). Everything else goes through SQLModel.
- **`basedpyright` is the type checker; do not run `mypy`.** `ruff` covers lint and format. `uv run basedpyright` runs in CI in `standard` mode (`[tool.basedpyright]` in `pyproject.toml`), against `.basedpyright/baseline.json`, which holds the 226 errors present when the check was added (mostly SQLModel typing, such as `.desc()` on a datetime column). CI fails on an error not in the baseline. After you fix baselined errors, run `uv run basedpyright --writebaseline` and commit the smaller file. Never run it to hide a new error.

## Environment variables

`settings.py` is the authoritative inventory of every setting and its type. Settings are read with `pydantic-settings`.

| Variable | Purpose |
|---|---|
| `DATABASE_URL` | Postgres connection string for the read-only role. |
| `BASIC_AUTH_USERNAME`, `BASIC_AUTH_PASSWORD` | `website.py` only. Required unless `PUBLIC_MODE` is true: the site does not start without them. |
| `PUBLIC_MODE` | Only `true` (any case) turns basic auth and the noindex header off in `website.py`, and turns off the API's `/docs`, `/redoc` and `/openapi.json` in `main.py`; anything else, or unset, keeps them on. |
| `IS_UNRELEASED_ENDPOINTS_ENABLED` | Optional, off unless set to `true`. Turns on every endpoint whose router depends on `validate_can_read_unreleased_endpoint`; off, each answers 404 `endpoint.not_found`. The routes stay in the app, so the API contract test still covers them. A change needs a restart. `GET /bills/{report_slug}`, `GET /acts/{sso_code}/people` and `GET /people/{person_id}/bills` are behind it. `GET /acts`, `GET /acts/{sso_code}` and the `act` parameter of `GET /search/speeches` are not. The page previews and the `noindex` tag of the Act pages do not read the setting. |
| `FRONTEND_DIST_PATH` | `website.py` only. The built frontend; the `Dockerfile` sets it. |
| `TAKEDOWN_REPORT_SLUGS` | Optional. Report slugs separated by commas; each listed report answers 410 and drops out of every list. A secret, because the repo is public. See `docs/takedown.md`. |
| `GOATCOUNTER_SITE_URL`, `GOATCOUNTER_API_TOKEN` | Optional. The GoatCounter site's origin, such as `https://example.goatcounter.com`, and an API token. Preview-bot fetches are sent only while both are set. |
| `SITE_URL` | Optional. The site's origin, such as `https://example.sg`, for the `og:url` preview tag and the canonical link, which drops the query, and for the sitemap's absolute URLs; the tags are left out and the sitemap answers 404 while unset. |

Never put a secret in code or in an example env file.

## Style docs

- **`STYLE.md`** is the resident summary of the coding rules. Follow it when writing or reviewing code. It covers naming, layers, control flow and failure, types and data, the HTTP surface, and comments.
- **`STYLE-RULINGS.md`** is the append-only log of numbered rulings (R1 onward) behind `STYLE.md`. Where the two disagree, the ruling governs. A new convention is recorded there first and propagated to `STYLE.md` in the same commit.

Rules that bite most often:

- Spell names out in full, with `is_` on every boolean (`STYLE.md`, Naming).
- No comments or docstrings, apart from the three licensed shapes (`STYLE.md`, Comments, diffs and deploys).
- Attempt the operation and catch the failure outside `validators/` (`STYLE.md`, Control flow and failure).
- Annotate every signature, but never the return type of `__init__` (`STYLE.md`, Types and data).
- Build only what the current change needs (`STYLE.md`, Layers).

## Git

- Commit straight to `master`. Do not create branches.
- Conventional Commits: `feat:`, `fix:`, `chore:`, `refactor:`, `docs:` followed by a short description.
- No attribution trailers or co-author lines in commits.
- Run `uv run ruff check .` and `uv run ruff format .` before every commit, and confirm `uv run fastapi dev` starts without errors.
