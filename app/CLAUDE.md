# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

`app/` is the React frontend for Hansard, a web app for browsing Singapore Parliament Hansard records. The data lives in a Postgres database owned by a separate scraper repo. `api/` (a sibling of `app/`) is a read-only FastAPI backend that serves that data. This frontend talks only to `api/`.

There are no tests, no Playwright, no Storybook and no auth.

**Stack**

- pnpm, TypeScript, Vite 8
- React 19.3
- Tailwind 4.3 (CSS-first, no `tailwind.config.js`)
- shadcn (CLI 4.x, Tailwind v4 mode, `tw-animate-css`) and `lucide-react` icons
- TanStack Router (file-based), TanStack Query, TanStack Table
- React Hook Form + Zod
- `sonner` for toasts

Code conventions live in [STYLE.md](STYLE.md). This file covers layout, commands and how the pieces fit together. When the two overlap, the section named in STYLE.md wins.

## Commands

Run these from `app/`.

```bash
pnpm install     # install dependencies
pnpm dev         # Vite dev server
pnpm build       # tsc, then vite build
pnpm lint        # ESLint
pnpm format      # Prettier
pnpm palette     # regenerate src/palette.css from src/palette/palette.ts
pnpm contrast    # check the generated tokens are current and every colour pair meets WCAG AA
```

Node 24 comes from asdf. The `.tool-versions` file is at the repo root, and `package.json` sets `engines.node` to 24. Dependencies use exact version pins, so do not add `^` or `~` ranges.

## Architecture patterns

### Routing

TanStack Router with file-based routes in `src/routes/`. The router plugin in `vite.config.ts` regenerates `src/routeTree.gen.ts` on save. Do not edit that file or commit it.

- `__root.tsx` is the root layout.
- `index.tsx` is `/`.
- `design.tsx` is `/design`.
- Route files use `kebab-case`. Dynamic segments use `$param`, for example `$sittingId.tsx`.

A new route exports `Route` from `createFileRoute('/path')({ component })`. Read params with `Route.useParams()` and search params with `Route.useSearch()`. Use `<Link to="...">` or `useNavigate()` for navigation, so paths stay type-checked.

### API layer

`src/api/client.ts` is the only HTTP client. It is a typed `fetch` wrapper exporting `apiGet<T>(path, init?)`, `apiPost<T>(path, body, init?)` and matching helpers for the other methods. Each returns the parsed JSON body typed as `T`. On a non-2xx response it throws `ApiError`, which carries `status` and `body`. There is no axios in this project and none should be added.

Server state goes through TanStack Query hooks, one file and one exported hook per endpoint, grouped by feature folder under `src/api/`. For hook shape, query keys, request and response interfaces, unwrapping, cache invalidation and conditional queries, follow the STYLE.md section "API Hooks".

The backend is read-only, so most hooks are queries. Mutation hooks follow the same STYLE.md rules if a POST endpoint is added.

### Components

- `components/ui/` holds shadcn primitives. Edit them only to add variants or sizes (see STYLE.md "Buttons").
- Feature components live in `components/<feature>/`.
- Naming follows STYLE.md "File and Folder Naming" and "Component Naming".
- Loading, error and empty states follow STYLE.md "Page Loading States" and "Error Notices".
- Dialogs follow STYLE.md "Dialogs".

### Forms

React Hook Form with a Zod resolver. The schema lives in the same file as the form. Rules for schema placement, enum fields, mutation ownership, reset and pending state are in the STYLE.md "Forms" section.

### Tables

TanStack Table, split into the file layout described in STYLE.md "Tables". Always set `getRowId`.

### State

- Server state: TanStack Query.
- Local state: `useState` with an explicit type parameter (STYLE.md "State Typing").
- URL state: route search params through the router.
- Per-resource session state: `sessionStorage` with the key pattern in STYLE.md "SessionStorage Keys".

### Theming and styling

Light and dark themes use the class strategy: the `.dark` class sits on the `html` element. Colour tokens are CSS variables generated for `:root` and `.dark` into `src/palette.css` from `src/palette/palette.ts`, then registered in the `@theme` block in `src/index.css` so Tailwind generates the utilities. There is no `tailwind.config.js`.

Use semantic tokens only. The colour rules, animation rules and transition table are in STYLE.md "Styling". A new colour is added to `src/palette/palette.ts` (a named colour plus the tokens that use it), then `pnpm palette` regenerates `src/palette.css` and `pnpm contrast` checks it. Spacing, type scale, radius, breakpoints and motion follow SGDS v3 as mapped in `docs/sgds-tokens.md`.

Use `cn()` from `@/lib/utils` for conditional classes.

### Notifications

Use `sonner` for toasts. Inline and page-level errors follow STYLE.md "Error Display" and "Error Notices".

## Adding a feature

1. Add the endpoint hook at `src/api/<feature>/<verb><Resource>.ts`. Put the request and response interfaces in the same file.
2. Add shared types to `src/types/<feature>/interfaces.ts` if more than one file needs them.
3. Add enums and constants to `src/constants/<feature>/enums.ts` and `constants.ts`.
4. Add components under `src/components/<feature>/`.
5. Add a route file under `src/routes/`. Save it and let the plugin regenerate the route tree.
6. Run `pnpm lint` and `pnpm build`.

## Adding a shadcn component

Use the shadcn CLI. It reads `components.json`, which sets Tailwind v4 mode, the `@/` aliases and `lucide` as the icon library.

```bash
pnpm dlx shadcn@latest add <component-name>
```

The component lands in `src/components/ui/`. If a button needs a new look, add a variant or size to `button.tsx` as STYLE.md "Buttons" describes. Do not override it with `className`.

## Path aliases

`@/` maps to `src/`. Use it for every cross-folder import.

```typescript
import { Button } from '@/components/ui/button' // good
import { Button } from '../../../components/ui/button' // avoid
```

The alias is set in `vite.config.ts` and in the tsconfig files. Change all of them together if it ever moves.

## Git

Commit straight to master. Use Conventional Commits (`feat:`, `fix:`, `chore:`, and so on). Do not add attribution trailers.

## Common issues

**Route tree not updating**

- Save the route file again.
- Restart `pnpm dev`.
- Check the route file for TypeScript errors.

**Type errors on `to` or `params` in `Link` or `navigate`**

- Confirm `src/routeTree.gen.ts` exists. Run `pnpm dev` once to generate it.
- Check the path string matches the file name under `src/routes/`.

**API calls fail**

- Check `api/` is running on the URL in `VITE_API_URL`.
- Look at the request in the browser Network tab. A failed call surfaces as an `ApiError` with the HTTP `status`.
- A CORS error in the console means the backend is not allowing the dev server origin.

**Styling not applying**

- Check the class uses a token that exists in `src/index.css`. A typo in a token name produces no style and no error.
- A new token needs a variable in both `:root` and `.dark`, plus an entry in `@theme`.
- Use `cn()` for dynamic classes.

**Dark mode not switching**

- Confirm `.dark` is on the `html` element, not on `body`.
